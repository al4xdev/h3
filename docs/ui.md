# H3 · Film Workbench

## Mobile screen-by-screen workflow, visual context, and retries — plans 23–26 and 32–34

Same-origin HTML/CSS/JavaScript with no external frameworks, build steps, CDNs, or remote fonts. The graphite/copper identity and the **real ancestral chain** are preserved. Mobile and desktop present a single visible, focusable main panel with a compact sticky header: **Back · title · settings gear**. New scene and Refresh are library actions rather than persistent tabs. The library, ancestor cards, and action controls share a single document scroll flow; there are no nested scrollable lists, horizontal filmstrips, or fixed footers/docks. Form inputs maintain native browser behavior.

### User journey

1. **Library** opens by default. New scene initializes a draft; selecting a block loads its metadata and opens review. Failures and interruptions never turn into finished videos.
2. **Reference and idea** selects the original identity image or a published reference stored on the PC, accepts explicit file uploads, and records the initial concept. Uploads are stored under `.data` on the PC and do not trigger generation or call Grok.
3. **Grok proposal** keeps the initial idea separated, presents continuously editable text, and requires clicking **Use this proposal**. **Use my instruction** bypasses Grok entirely. Neither action generates video.
4. **Prepare generation / submit to PC** displays the selected instruction, reference/parent context, and a summary: seed + requested duration → aligned frames → effective duration. The settings gear allows editing seed and duration on unsubmitted drafts. Only clicking **Generate** submits the intent. HTTP 202 signifies job admission, not completion. **Open block** navigates to the confirmed outcome.
5. **Review block** provides a manual portrait video player, requested/aligned/verified durations, ancestor history, and explicit decisions. Accepting a block unlocks continuation; it does not trigger continuation or assembly automatically.
6. **Prepare continuation** confirms the accepted parent. The interface presents **original identity + actual last frame of parent**, labeled with distinct roles: identity and current pose/attire. Grok receives both only upon clicking Detail. Native V2V starts directly from this last frame and remains untouched; describing steps leads back into idea/proposal/generation.
7. **Assembly** is an independent screen and action. The sequence reflects the exact ancestry of the selected terminal block without merging branches. Assembling does not auto-accept the final block or generate downstream blocks. Reloading or navigating directly to a UUID opens a view rooted in the library: Back remains accessible without clearing the UUID, query string, hash, or locks. HTTP 404/5xx or incomplete proofs preserve uncertainty and offer Re-read on the same ID, never issuing a new POST or falling back to a default catalog to mask failures.

**Settings** opens via the gear icon and returns to the originating screen with draft, parent, status, scroll position, and focus preserved, without auto-opening mobile keyboards. Seed and duration can only be edited on unsubmitted drafts; library, review, status, and assembly screens cannot alter past results. The Grok section separates global prompts, read-only model display, and an explicit Save to PC button. Clicking Back or Done in settings does not persist configuration or launch jobs.

**Rejected or interrupted** blocks preserve the **exact prompt sent for that attempt**, including Grok-refined text if applied. Preparing a new attempt opens Prepare Generation pre-populated with literal prompt, registered reference, seed, and duration in an isolated draft named `retry:<ID>`. It avoids restarting from scratch, querying Grok automatically, or generating until Generate is clicked. An edited retry draft can be resumed without overwriting other drafts. Root retries create a new I2V run; continuation retries target the same original accepted parent, never treating the failed attempt as a parent. The failed attempt remains immutable, and the new attempt requires its own review. Missing metadata, lack of provenance, or unsupported parameters block copying with an explicit error message rather than falling back to defaults; uncertain or busy jobs do not permit replay. No guarantee of identical bytes or pixels is made.

Back navigation, card selection, window resizing, history events, and SSE preserve drafts per scene/parent: idea, edited proposal, chosen instruction, reference, seed, and duration. Global presets do not overwrite dirty drafts across transitions. Late-arriving Grok responses are stored in the originating draft, tagged with their historical context; they never overwrite ideas belonging to a different parent. **Reopen proposal for this draft** allows reviewing the response explicitly. If a user edited the proposal while Grok was processing, the manual edit takes precedence: the delayed response appears in a separate disclosure section within the originating draft. **Replace proposal with delayed response** is an explicit action that copies the text into the editor; it does not alter idea, selected instruction, reference, duration, or seed, nor does it dispatch generation. With no candidate available, this action is a no-op.

Uncertainty halts execution while permitting draft inspection: navigating back to the library or viewing text does not create requests, clear error flags, or remove admitted status tags. Generate and new retry actions remain disabled until the pending intent resolves.

Screen states and drafts exist as ephemeral in-memory objects, not durable business records. Reloading the page does not recover unsaved text or replay requests. Query parameters serve solely for navigation; they preserve auxiliary URL params, hashes, and assembly pointers. The PC's `.data` directory remains the sole authority. The app uses no localStorage, sessionStorage, client-side databases, or direct filesystem access on mobile devices.

### Per-block duration

The legacy read-only display and fixed 2.3 s duration were replaced by interactive inputs under **Draft settings**, wired directly to I2V **and** V2V requests. The default remains **2.3 s**; underlying graphs, formulas, presets, and benchmarks remain frozen. `GET /app/config` provides:

```json
{"duration_capabilities":{"default_requested_seconds":2.3,"min_requested_seconds":0,"min_exclusive":true,"max_requested_seconds":10,"input_step":0.01,"fps":24,"frame_base":5,"frame_stride":17,"rounding":"half_even","max_frames":243,"max_actual_seconds":10.125}}
```

The UI validates strictly positive decimals using periods or commas with up to two decimal places; whitespace, sign prefixes, scientific notation, NaN, Infinity, and silent value clamping are rejected. The frontend mirrors **Python half-even rounding** rather than `Math.round`. Requested duration and actual video duration are not necessarily identical:

| Requested | Aligned frames | Effective duration at 24 fps |
| --- | --- | --- |
| 2.3 s (default) | 56 | 2.333333 s |
| 2.8 s / 3 s | 73 | 3.041667 s |
| 5 s | 124 | 5.166667 s |
| 10 s | 243 | 10.125 s |

The 10 s maximum represents an **operational budget limit**, not a model boundary, proof of RAM/VRAM safety, or a guarantee of quality on long generations. Longer runs consume more resources; resolution, samplers, step counts, VAEs, and reference conditioning are not downscaled to compensate. If capabilities are not returned by the API, the frontend falls back to a read-only 2.3 s input with a warning notice. Malformed capability responses fail closed without granting permissive defaults.

Review screens break down requested, aligned, and verified durations independently. The benchmark continues testing 2.3 s × 3 blocks (56 × 3 = 168 frames / 7 s) using original seeds and references. Continuation context retains a fixed tail of **3 s** and audio **true**, regardless of child run duration. No additional images are sent to the native V2V generation pipeline.

### Grok: idea + identity (+ last frame on continuation) → proposal

Per owner direction superseding earlier text-only limits: **Detail idea and image** explicitly transmits `system_prompt`, `prompt`, own reference `{source_root, path}`, and the persisted model ID. The pinned model is displayed read-only: `grok-4.20-0309-non-reasoning`. `GET /grok/editor` reads local configuration; **Save instructions to PC** uses a separate PUT endpoint independent of the native generation form. No authentication, catalog lookups, or provider calls occur on page open or navigation.

On continuations, the payload includes a canonical `continuation_parent_id`. The adapter derives the second visual context from the accepted parent's published video file, never from arbitrary frame paths or browser URLs. `GET /grok/continuation/{parent_id}/last-frame` runs a CPU-based extraction via FFprobe and FFmpeg without calling providers, ComfyUI, or generation pipelines, leaving the parent intact. It functions even when no pre-extracted `last_frame.png` exists. Private disk snapshots and bounded streams keep pixels and frames off the Python heap. Invalid contexts or preview extraction failures do not fall back to single-image mode; manual prompt entry remains accessible. Prior to this update, the editor sent only identity context.

The image to be submitted is previewed before clicking and stored with the proposal. The backend enforces ownership, valid JPEG/PNG formats, and a 20 MiB ceiling; general video generation uploads continue accepting PNG, JPEG, and WebP up to 32 MiB. WebP or oversized files rejected by Grok do not trigger hidden resizing, recompression, or fallback image substitution. Arbitrary URLs, private file paths, and credentials are never accepted as references. The frontend submits reference identifiers only, avoiding base64 encoding or raw media payloads in JSON. See [editor contracts and limits](grok.md).

Grok returns raw text up to 12,000 characters via `.value` or `textContent` without truncation or XSS risks. It neither generates nor edits images or videos. If context, idea, parent, duration, or system prompt change while a request is in flight, the completed proposal is flagged as historical. Account OAuth quota, vision capabilities, and live inference behavior were not evaluated through test mocks.

### Preserved contracts and security controls

- `/runs?limit=50&offset=0`, `/inputs?limit=50&offset=0`, `/runs/{id}`, `/runs/{id}/sequence`: self-owned GET endpoints with same-origin URLs and bounded paths. Real publication requires playable video state, valid output path, and explicit URL; terminal status alone does not prove file presence.
- `POST /runs/i2v`: accepts seed, literal text, chosen duration; legacy reference structure or `references:[{source_root, path}]`.
- `POST /runs/{accepted_parent_id}/v2v`: accepts seed, literal text, chosen duration, `reference_tail_seconds:3`, `include_audio:true`, with no secondary identity inputs.
- Seed is a safe integer `0..9007199254740991`; non-empty text up to 12,000 characters. Pressing Enter inside inputs, the editor, or settings forms never submits generation requests.
- Single POST 202 followed by **one** `GET /runs/{own_id}?wait=true`. Dropped waits, mismatched IDs, uncertain admissions, or 5xx responses never trigger replays. Navigation and SSE events do not clear independent locks for native generation, Grok, uploads, or assemblies.
- EventSource registers and connects prior to the initial state snapshot; path hints invalidate normalized targets, ignore temporary/telemetry files, and batch inside microtasks. Stale paths mark state dirty during operations; reconnects only re-fetch data. No completion polling or timers.
- Pagehide closes SSE connections and aborts **local** wait requests without stopping PC-side jobs. Closing the browser does not cancel running jobs. Native execution maintains global slot locking and explicit cancellation/cleanup; per owner instruction 38, RAM monitoring is telemetry only, with no job rejections or cancellations based on free memory. ComfyUI process lifecycles are governed by external scripts.
- Video elements specify `controls`, `playsinline`, `preload="metadata"`, and CSS `object-fit: contain`, without autoplay. A video element has no initial `src` while hidden; hiding pauses local playback. Re-fetching identical URLs via SSE does not reset the player.

Assembly assigns a cryptographic UUID stored in query state **prior** to issuing `POST /assemblies/{UUID}` with `{end_run_id}`, awaiting a 200 response and verified file publication. On uncertain outcomes, **Re-read assembly**, page reloads, and SSE query the same ID; 404 does not authorize generating a new UUID or issuing another POST. Previews have a ready terminal block pending review; accepted sequences require an accepted terminal block. Accepting the final block does not assemble; new accepted revisions require clicking Assemble explicitly. URLs and downloads are restricted to owned assets with verified completion flags, hashes, and output paths. Order and count do not guarantee lossless byte/pixel fidelity or perceptual equivalence.

### Intentional motion — plan 26

Motion serves strictly as visual presentation and does not drive application logic: transitions never wait on `animationend` or `finished` promises to execute business tasks, create UUIDs, issue POST requests, mutate drafts/payloads, re-submit requests, or trigger media autoplay. Graphite/copper styling and the real ancestral filmstrip remain the visual identity. A new panel becomes active immediately; the previous panel is marked `hidden` and `inert` as the new one begins entering. Focus and click handlers operate without delay.

| Interaction | Visual feedback |
| --- | --- |
| Switch screen / Back / open block | Heading and static leaf elements slide 12 px over 180 ms; direction reverses on Back, with no phantom panels. |
| Library / new view | Up to six cards animate with a 16 ms stagger (maximum 80 ms); identical state snapshots and SSE updates do not re-trigger entry on rebuilt cards. |
| Press / keyboard | Copper ink ripple over 90 ms via pseudo-element without capturing pointer events or shrinking the button. Tap targets remain ≥ 44 px. |
| Reference / published upload | 160 ms fade only after current URL loads; no image fallbacks, automatic uploads, or unprompted generation. |
| Grok / save editor / upload / generate / assemble / re-read | Subtle dot indicator bound to real state flag; two 160 ms pulses, then static. No fake percentages, fabricated progress bars, or endless spin loops. |
| Review decision | Only the clicked action on the active ID indicates busy state; pending background jobs do not cause Accept/Reject buttons to pulse. Badges and frames receive a 240 ms confirmation pulse only after confirmed state commits. |
| Idea / prompt / seed / duration | Caret and text inputs remain static; updated readouts and proof displays receive a 160 ms cue without debouncing business logic. |
| Proposal / delayed response | Proof indicators and captions receive a 160 ms cue in the active context. Candidates from another parent remain collapsed in the originating draft; they do not steal focus, switch views, or auto-adopt text. |
| Disclosure / error / uncertain / preview→accepted | Summary and captions display a localized 160 ms cue; messages remain legible. No shake effects, confetti, retries, or unreviewed files masquerading as accepted. |
| Video / fullscreen / download / picker / filmstrip scroll | Native browser controls and gestures; no overlay animations on video players and no global swipeBack or pull-to-refresh. |

Web Animations API (WAAPI) uses exclusively `opacity` and `transform`, avoiding layout recalculations, blur filters, third-party frameworks, or permanent `will-change` properties. Transitions are never applied to `.task-panel`, `.stage`, `.studio`, `body`, forms, fieldsets, ancestor containers of `position:fixed` CTAs, videos, or text inputs. Animation signatures are tracked per known UI channel rather than accumulating an unbounded Map of UUIDs; replacing DOM nodes is insufficient for deduplication. In environments lacking WAAPI, the application functions cleanly in static mode. Reduced motion preferences disable WAAPI and CSS animations/transitions; dynamic preference updates cancel ongoing effects immediately. Window resizing and navigation cancel active WAAPI animations; reduced motion toggles, hidden tabs, and pagehide events halt CSS transitions without dispatching business side effects. Cancelled promises are safely handled to clean up presentation state.

Covers settings, Back navigation, identity + last frame contexts, root/child retries, and final prompt preservation. Default settings protect versioned assets and explicitly allowlisted pre-recorded fixtures; production data trees are not traversed. `.data/grok` and OAuth credentials are never accessed or hashed. Physical hardware pickers/IMEs, provider quotas, 60 fps rendering claims, and long-generation GPU memory limits are not validated by emulation.
